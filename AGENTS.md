# Elsepin project guide

- Version/build policy: every newly packaged code revision gets a new monotonically increasing `CURRENT_PROJECT_VERSION`, even before physical-phone acceptance. An exact-source retry may keep its candidate number. Keep app and extension values aligned in `project.yml`, and record source/run evidence. Official release notes must carry matching `Build N` and `<!-- elsepin-build: N -->` metadata from the verified IPA. Do not publish merely to update this metadata.
- Cost preference: use a smaller available model for bounded metadata, documentation and test-support tasks when delegation saves work. Preserve technical meaning when humanizing copy. The lead remains responsible for integration and evidence; do not switch provider billing or expose credentials to save tokens.

- Source origin is now `HonorableLordFishy/Elsepin`. The old `N3moStudio/Elsepin` is an empty private placeholder that prevents redirects; never push source there. Read CURRENT-WORK.md for current visibility authorization and the pending owner-only visibility change.
- Read [current work](docs/CURRENT-WORK.md) when starting a workstream and [chat workflow](docs/CHAT-WORKFLOW.md) for handoffs or optional external supporting analysis.
- App sources remain under `Locus/`, extension under `LocusActivity/`, portable rules/tests under `Shared/` and `Tests/`. The visible product is Elsepin; do not blindly rename compatibility identifiers. Helpers are in `Companion/` and `CloudFindMy/`; website is in `website/`.
- Before building, read [building](docs/BUILDING.md). GitHub `origin` is private again by owner request (15 November); public downloads/docs stay in Elsepin-Releases. Recheck private Actions allowance before future builds; use the manual `build-ipa.yml` workflow on the current development branch. GitLab remains private. Codemagic free minutes are exhausted; do not enable paid billing or retry unchanged quota blocks. Keep both remotes. Local native builds require macOS/Xcode and XcodeGen; discover tools before assuming availability. `project.yml` is authoritative; regenerate `Locus.xcodeproj` before native builds.
- Checks include `swift test`, `python3 -m unittest discover -s scripts/tests -v`, identity/appearance checks and helper tests documented in BUILDING.md. Portable tests do not prove device pairing, signing, accessibility, gestures, battery or provider accounts.
- Before identity changes read [brand map](docs/BRAND-MAP.md); before backup changes read [backups](docs/BACKUPS.md). Preserve defaults/Keychain keys, bundle IDs, app group and existing backup formats unless implementing an explicit migration. Retain required third-party notices and keep credentials out of source.
- Elsepin remains the full product: never copy Veypax paid gates into it. Widgets prepare a pin and always require manual in-app confirmation before movement. Keep Stop available.
- Locate related code with [app map](docs/APP-MAP.md); maintain historical evidence in [change ledger](docs/CHANGE-LEDGER.md). User approval is still required by task scope for publication; a handoff does not grant it.
- Before visual polish, read [UI polish constraints and evidence](docs/UI-POLISH.md). Supplemental web design skills must preserve Elsepin's approved native appearance and interactions.
- Group related editor controls with spacing/dividers; do not give every small control its own rounded card. Preserve native Back/edge-swipe in pushed editors. See UI-POLISH for the approved planner structure.
- Deliver only the latest requested test IPA to `C:/Users/naith/Desktop/ipa/My Projects (N3mo Studio)`. Replace older Elsepin IPAs there only after the replacement is complete; leave other apps untouched. No checksum sidecars, ZIP bundles, logs or extra files in that folder. Keep build diagnostics in ignored `.build/artifacts/`.
- For battery work, consult [energy review](docs/ENERGY-REVIEW.md) and the installed Axiom performance/location guidance; source review is not measured battery evidence.

- Before changing library/preference persistence, read [Dev Mode isolation](docs/DEV-MODE.md). Keep demo writes isolated, capture destinations before async work, and preserve real session-clear evidence and credentials.
